# 크롤링으로 찾는 2026년 뷰티 트렌드와 아누아 심층 리서치

**자료 수집 → 텍스트 분석 → 트렌드 후보 발견 → 관련 아누아 제품 심층 조사.**
자기소개서 2번에는 분석 결과를, 3번에는 브랜드·제품까지 파고든 과정을 활용한다. 자기소개서는 분석 후 작성한다.

## 더블클릭으로 화면 보기

1. 프로젝트 폴더의 **start.bat**을 더블클릭한다.
2. `1` 또는 Enter: 저장된 자료 분석 후 브라우저에서 결과 화면 열기.
3. `2`: 공개 기사 추가 수집 → 분석 → 결과 화면 열기. 실행 창에 진행 상황이 표시된다.

이미 생성된 화면만 보려면 **outputs/대시보드.html**을 더블클릭해도 된다. 인터넷 서버나 별도 웹 앱 설치는 필요 없다.
기사 출처·게시 월·제목 검색·아누아 필터를 변경하면 차트와 기사 목록이 함께 바뀐다. 기사 제목은 원문 링크다.
화면은 생성 시점의 데이터이므로 브라우저 새로고침만으로 크롤링하지 않는다. 새 자료를 받으려면 start.bat에서 2번을 선택한다.
수집 범위는 현재 2025-01-01~2026-10-11이고 최신 목록 두 페이지다. 범위 변경은 아래 CLI 또는 launcher.py에서 한다.
`dashboard.py`가 `dashboard_template.html`과 실제 자료로 화면을 생성한다.

## 실행 방법 (PowerShell)

터미널 위치를 프로젝트 폴더(`projects/beauty-trend-analysis`)로 맞춘다. 처음 내려받은 경우 아래 설치 명령으로 `.venv`를 먼저 준비한다. 가상환경과 원문 데이터는 저장소에 포함하지 않는다.

```powershell
# 공개 기사 수집 (출처별 최대 상세 요청 20개, 최소 2초 간격)
& '.\.venv\Scripts\python.exe' -X utf8 pipeline.py crawl --pages 2 --limit 20 --start 2025-01-01 --end 2026-10-11

# 분석
& '.\.venv\Scripts\python.exe' -X utf8 pipeline.py analyze --year 2026 --cutoff 2026-10-11

# 로직 검증
& '.\.venv\Scripts\python.exe' -X utf8 -m unittest -v test_pipeline.py
```

새 컴퓨터: `python -m venv .venv` 후 `.venv\Scripts\python.exe -m pip install -r requirements.txt`.
개발 당시 검증 버전은 `environment_versions.txt`에 기록한다. 최초 실행에서는 자료가 없으므로 수집 명령 또는 start.bat의 2번부터 실행한다.
`시작하기.ipynb`는 단계별 실행 노트북이다. 필요한 경우 커널 환경에 위 requirements를 설치한다.

## 수집 범위

- 코스인코리아: 전체 뉴스 목록에서 기사 URL을 발견하고 본문 영역·JSON-LD 게시일 추출.
- 화해 비즈니스: 지정된 리포트의 공개 섹션 일부. 기사 모집단과 섞지 않고 참고 자료로 보관.
- 아누아 공식몰·소비자 리뷰: 자동 수집 미구현. 앞선 공식몰 정책 확인은 403 응답이었다.

robots.txt 정책 확인 후 요청한다. 403/429/정책 확인 실패·리디렉션은 로그에 남기고 건너뛴다. robots 허용은 재배포 허락을 뜻하지 않는다. CAPTCHA·로그인을 우회하지 않는다.
`config.json`에서 출처와 선택자를 수정할 수 있다. `inspect_sources.py`는 개발용 구조 확인 스크립트다.

**날짜 필터만으로 해당 기간 전체 자료가 수집되는 것은 아니다.** 최신 목록 몇 페이지에는 과거 기사가 없다. 범위를 점진적으로 늘린 뒤 `coverage.csv`에서 연도·월별 자료를 확인한다.

```powershell
& '.\.venv\Scripts\python.exe' -X utf8 pipeline.py crawl --source cosin --page-start 3 --pages 3 --limit 60 --start 2025-01-01 --end 2026-10-11
```

요청 상한 때문에 발견한 URL을 전부 읽지 않을 수도 있다. 같은 명령을 재실행하면 저장한 URL은 건너뛰고 남은 URL을 읽는다. 과거 기간 전체 수집은 아직 실행하지 않았다.

## 분석 기준

1. 동일 URL·공백 정규화한 동일 본문을 중복 제거한다. 약간 바뀐 보도자료 재전재는 수동 확인해야 한다.
2. TF-IDF로 단어와 2단어 표현을 탐색한다. 한국어 형태소 분석이 아니므로 조사·어미에 따라 표현이 나뉠 수 있다.
3. 개념 사전은 사람이 정한 출발점이며 트렌드 결론이 아니다. 원문 검토 후 확장하고 변경 근거를 남긴다.
4. 같은 개념이 한 기사에 반복돼도 한 번만 센다. 분모는 해당 출처·월의 수집 기사 수다.
5. 출처별로 전년 1월 1일~같은 월일과 올해를 비교한다. 자료가 없으면 결측이다. 최소 30건 경고는 통계적 유의성 기준이 아니다.
6. 화해의 목적 선택 표본은 비교 분모에서 제외한다. 독립적인 뉴스 출처는 현재 하나이므로 다매체 검증은 미완료다.
7. 전체 뉴스에는 산업·기업 기사도 포함된다. 관련어 필터는 스킨케어 전용 분류기가 아니므로 기사 유형을 검토해야 한다.
8. 언급량을 수요·매출·임상 효능으로 해석하지 않는다. TF-IDF는 증가율이나 객관적인 중요도 순위가 아니다.

## 아누아 제품 심층 조사로 연결

원문과 기간별 자료를 검토해 핵심 키워드를 선정한 다음, 관련 아누아 제품과 비교 제품의 성분·효능 주장·제형·용량·가격을 조사한다. 키워드와 제품은 아직 미확정이다.

`review-code`는 별도로 확보한 실제 리뷰의 속성 검토표를 만든다. 리뷰 수집기나 감성 모델은 아니다.
JSONL은 한 줄당 객체 하나이며 필수 항목은 `source`, `review_id`, `product_id`, `text`, `url`, `published_at`(YYYY-MM-DD)다. 작성자 이름은 필요하지 않다.

```powershell
& '.\.venv\Scripts\python.exe' -X utf8 pipeline.py review-code --input data/reviews.jsonl
```

출처·제품·리뷰 ID가 같은 중복을 제거하고 보습·진정·사용감 등 속성별 행을 만든다. `sentiment_manual`에 긍정/부정/혼합/판단불가를, `evidence_manual`에 근거를 직접 기록한다. “안 끈적인다”처럼 부정어 문맥이 있어 감성을 단어만으로 단정하지 않는다.

## 다음 단계

본문·게시일 수동 점검 → 기간별 표본 확장 → 두 번째 독립 매체 확보 → 기사 유형·재전재 검토 → 키워드 선정 → 아누아 제품·리뷰 심층 조사.
소량 실행 결과는 프로그램 검증용이며, 현재 결과만으로 2026년 트렌드를 주장하지 않는다. 원문은 내부 검증용으로 두고 포트폴리오에는 집계·출처 위주로 제시한다.
